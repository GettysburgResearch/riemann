## Four questions before using an artifact

**What are the primitive inputs?** Exact integers/rationals and independently enclosed special-function values are different assurance classes. Check the actual function, source coefficients, node set, normalization and division guards.

**What domain is completely covered?** A finite certificate must account for every required cell, activation, contour edge, divisor slab or tree terminal. A continuum theorem needs an interpolation, remainder or enclosure argument covering the gaps between samples.

**Which arithmetic and checker are trusted?** Ordinary high precision is not directed rounding. Decimal serialization can destroy an enclosure. Follow the current replacement's documented commands and acceptance predicate, not an obsolete producer or a generic `verified:true` flag.

**Which analytic inputs remain?** A finite pressure inequality is not its zeta trace adapter. A primitive matrix box is not a global sign. A formal build is not evidence that an input package describes the intended entire function.

## Reproduce or improve one object

Choose the current statement first, then use its linked source/evidence packet. Preserve the source version, exact inputs, output and arithmetic assumptions. An independent primitive implementation can be more informative than another run of the same checker. Report a failure or inconclusive enclosure as such; it is not automatically a counterexample to the theorem.

Exploratory eigenvalues, finite phase efficiencies and high-precision plots remain useful reconnaissance when labeled non-certifying. They must not enter the accepted baseline through a positive trend alone. [Concrete evidence tasks](OPEN_CUTS.md#bounded-contributions) include the Pick primitive replay and a continuum Schur lower bound.
