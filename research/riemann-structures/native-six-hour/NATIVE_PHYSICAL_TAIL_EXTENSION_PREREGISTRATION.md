with the same 128 MiB worker target and 2 GiB free-memory reserve.

mathematical UNKNOWN.

The new calibration horizon is exactly \(2^{20}\). A new implementation
must independently enumerate its aliases and reconstruct every one of
the frozen result's source terms, positive majorants, all36 row
coordinates, twenty prefixes, total bounds, matrix, tails, local tables,
inverse products, row sums and theta. Compare the complete exact
mathematical record with the prior capture, using canonical serialized
JSON rather than Python equality. In particular its UNKNOWN status
must remain unchanged.

After root freezes the new calibration artifact and the new owned
files, the only extension horizon is exactly
\[
                              H_{\rm ext}=2^{48}.
\]
The extension run must authenticate that freeze, establish that its
algorithm, declaration, replay note and tests are unchanged under LF
normalization, and freshly reproduce the new calibration before
processing the larger target. An arbitrary command-line horizon is
not accepted. The phase is called extension, not heldout.

The successful calibration is a replay acceptance event, not a
contractive mathematical result. It authorizes no modification of the
twenty fixed ratios or columns.

## 3. A new complete alias enumerator, not a cap override

For each ratio use the exact integer maximum
\[
            G_{a,b}(H)=\left\lfloor\sqrt{\left\lfloor
                                  H/(ab)\right\rfloor}\right\rfloor .
\]
At the extension target it is at most \(2^{24}\).
The new enumerator forms prime-power products
\(g=2^i3^j5^k\le G_{a,b}(H)\), then sorts them increasingly. It must
not scan all integers up to \(2^{24}\).

The enclosing exponent box has at most
\(25\cdot16\cdot11=4400\) triples: \(i\le24,j\le15,k\le10\).
Thus a fixed cap of 4400 aliases per ratio, twenty ratios and 88000
processed alias records is sufficient before applying the product
constraint. Every returned integer must be strictly increasing, unique,
supported on the three primes and at most its exact maximum. Completeness
comes from the exhaustive exponent box, not from a heuristic cutoff.

The new exponent decoder accepts only literal bounded integers.
It does not change the old decoder's \(2^{20}\) limit. Ratios still have
\(a,b\le900\) and local shifts at most nine. Alias local exponents are
at most24, so their shifted coefficient exponents are at most33.
The unchanged infinite-sum table uses exponents at most \(64+9=73\).
Both are inside the old coefficient cap80 and the old local-helper
cap64 on the unshifted exponent. No monkeypatch of an old cap is needed.

## 4. Complete coverage with bounded retained memory

For every ratio retain its complete ordered integer alias list,
count and exact maximum. Do not retain a large object for every source
and majorant vector at the larger horizon.

Instead, process each alias once and feed its complete exact record
into a SHA256 stream. The record contains the alias integer, all36
signed source coordinates in their canonical sparse encoding, and
all twenty nonnegative majorant coordinates. Use canonical encoded
JSON plus a newline as framing, with a versioned domain label and
the ordered ratio as the stream prefix. The framing and rational
spellings are part of the contract.

The artifact also retains the complete all36 signed row sum,
twenty positive-prefix sums, twenty infinite-majorant upper bounds,
twenty tail bounds, the full local64 tables, the twenty-by-twenty
matrix and tail matrix, both inverse identities, the exact
\(|A_H^{-1}|T_H\) matrix, all row sums and theta.

The digest records a fully recomputable stream; it is not a substitute
for replay. Every final check must regenerate every alias contribution,
all accumulators and the digest. At calibration, additionally compare
each freshly generated record directly with its corresponding frozen
old alias object before discarding it. This checks the stream convention
against the complete retained prior result.

Keep source bytes at32MiB and each new artifact at16MiB. Process one
alias and one row at a time; no dense observation Gram matrix, full
all-pairs source matrix, or global alias-object cache is introduced.
The reused bounded local caches keep their existing limits.

## 5. Outcome and scope rules

The extension records one of the existing mathematical statuses:

- PASS only if the actual exact theta is strictly less than one;
- UNKNOWN_TAIL_NOT_CONTRACTIVE for a verified inverse with theta at
  least one;
- UNKNOWN_SINGULAR_MINOR if the selected matrix is singular.

Type, source, coverage, digest, coefficient-bit, and resource failures
are acceptance refusals, not mathematical outcomes. No fallback minor,
higher bit cap, new local cutoff, or second larger horizon is permitted
within this registration.

If PASS occurs at \(2^{48}\), report that specific effective sufficient
threshold for all later integer horizons and the infinite observation.
It is not the first faithful horizon. The earlier tested range through900
and isolated \(2^{20}\) result remain separate. Nothing here bridges
every horizon from901 through \(2^{48}-1\).

If the extension is UNKNOWN or refused, the qualitative eventual
faithfulness theorem remains valid but no new effective threshold is
claimed. All earlier UNKNOWN artifacts remain unchanged and visible.
There is no energy minimum, optimizer-persistence, all-prime completion,
retained-gamma decoder or RH claim.
