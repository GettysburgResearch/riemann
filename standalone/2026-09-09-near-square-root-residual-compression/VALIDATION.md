# Execution record and trust boundary

## Bounded mathematical reconstruction

The sealed verifier reconstructs 597 bounded panels in nine named groups:
46 exact geometric-source projection/affine-budget panels; 12 exact geometric
jet polynomials; 64 finite Taylor-factorial budgets; 5 rank/log-power identities;
56 finite spectral/trace/comparison panels; 15 complete small period-mean panels;
256 independent Mobius comparisons; 128 native floor-prefix identities; and
15 complete formal-prime-log graph expansions. Counts are fixtures, not proofs
of 597 infinite mathematical statements.

All acceptance arithmetic is integer/Fraction standard-library Python. The
geometric-node projector tests use n_j=4*4^j, whose square roots are rational.
Their true logarithmic moment identities factor powers of log4. The code does
not pretend logs of arbitrary integers are rational. Finite spectral ordering
uses declared rational examples, not claimed computed zeta-source eigenvalues.
The small period means retain every period cell. They are not a new full-norm
minimum certificate or a large source campaign.

The normal and optimized producers emit identical mathematical result.json.
Both sealed accepting commands reconstruct that result and authenticate all
eight manifest entries and the exact nine-file regular-file inventory:

    python -I -S -B verify.py --check result.json
    python -I -S -B -O verify.py --check result.json

No assert implements acceptance. Duplicate JSON keys, floats, Boolean aliases
and changed source identity are rejected. `--emit` is producer mode; it does
not authenticate a packet and is not an acceptance command.

## Actual adverse CLI controls

Ten mutations are tested in each interpreter mode, after a pristine copied
packet passes: false RH status, false upper-bound status, Boolean numeric alias,
float alias, changed rank exponent, duplicate JSON, unsealed altered proof,
resealed extra file, parent drift, and resealed producer code omitting higher
prime powers. The last fails the independently expanded full graph formula.
These are twenty refusal subprocesses; four pristine controls are run across
the two partitions and two modes. Commands:

    python -I -S -B test_rejections.py --part 1
    python -I -S -B test_rejections.py --part 2
    python -I -S -B test_rejections.py --optimized --part 1
    python -I -S -B test_rejections.py --optimized --part 2

Semantic alterations are resealed to test reconstruction beyond hashes. A file
integrity rejection is not a mathematical refutation of an altered manuscript.
The parent source SHA is checked as a binding declaration, not a fresh byte-level
reproduction of every parent file. No parent Python or historical suite is run.

## Analytic scope and delivery scope

The complete infinite arguments are paper proofs. The approximate functional
equation is imported from DLMF25.9.3; the mean-square consequence and trace-tail
estimates are derived in PROOF.md, not established by finite numerical testing.
Bourgain's pointwise bound was inspected while exploring a preliminary weaker
argument, but is NOT used in the final claims. No numerical zeta integral,
unknown zero, special-function oracle or RH-conditional prime-error theorem is
used by the verifier. Implicit analytic constants are not numerically supplied.

The compressed spectral subspace is source-defined by a finite full-tail form;
its general high-rank construction is NOT executed here. There is no new native
minimum, window positivity, source-domain completeness, zero-free region or RH
proof. The coefficient-budgeted minimum remains unbounded by this paper at the
subpower scale. Independent mathematical review is required.

The downloadable add-only patch is tested in a temporary Git workspace with an
unrelated sentinel. All packet bytes and the packet subtree are independently
reconstructed and both accepting modes are replayed. A clean ZIP extraction is
likewise replayed. These are minimal-context delivery checks, not a full Riemann
checkout, remote CI, Lean/kernel build or independent human referee acceptance.
Publication receipt outside the sealed directory records the actual remote head
and whether publication succeeded; it must not be inferred from this document.
