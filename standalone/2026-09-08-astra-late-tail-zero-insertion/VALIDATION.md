## Trust and rejection contracts

The checker uses Python integers, fractions, and a small Gaussian-rational
class. There are no floating-point calculations or third-party dependencies.
Acceptance never uses `assert`. JSON rejects duplicate keys, floating values,
nonfinite constants and boolean aliases in integer fields. The flat nine-file
inventory and nonempty eight-entry manifest reject missing/extra files and
symlinks. The parent proof is bound by exact SHA256, Git blob and byte length.
A changed source lock is not accepted merely because its local hash is updated.

The test script runs one pristine CLI control and twelve distinct corrupted
CLI packets in each interpreter mode. Six semantic result changes are resealed
so that rejection is not only a checksum mismatch. The symlink test retains
identical file bytes and checks the input-path type. Windows symlink privilege
failure is not handled as an automatic pass: this script fails if it cannot
execute that test. No Windows run is claimed in the authoring environment.

The manifest authenticates artifact bytes relative to the published Git tree;
it is not a cryptographic proof of the mathematical text. Rewriting both a
checker and its manifest is outside its independent trust root. Infinite proof
steps require mathematical review.
