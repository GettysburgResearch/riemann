# BUB26 validation and publication boundary

## Mathematical scope

The manuscript gives proposed analytic component proofs. The executable does
not machine-prove Euler--Maclaurin, Binet, Harnack, Rouche, source convergence,
or the imported Conrey theorem. It reconstructs only the declared finite
integer/rational consequences. Independent mathematical review is outstanding.
RH and gap-free expanding-window confinement are explicitly not established.

The source error is reconstructed from the frozen parent. The parent's
height-30 numerical certificate is a historical dependency for orientation,
not a newly executed certificate or the source of the unbounded-band result.
The latter imports Conrey's published simple-central-zero proportion.

## Bounded reconstruction contract

`check.py --check result.json` authenticates the eight-file regular-file
inventory and all seven SHA256 entries, checks the parent source identity in
SOURCES.json, regenerates the complete expected typed JSON, and compares every
field. The accepted arithmetic is Python integers and exact Fractions.
JSON duplicate keys, float/nonfinite numbers and Boolean/integer aliases are
rejected. No assert implements the accepting predicate.

Reconstructed groups are:

- exact logarithm, Euler--Maclaurin and contraction constants;
- five displayed height/resolution/depth schedules;
- 29 prescribed dyadic schedules, j=4,...,32;
- 20 multiplicity and reflected-pair local counts;
- nine literal third-moment stages, independently compared with the closed law;
- one complete synthetic degree-20 real even polynomial, with twenty distinct
  explicitly evaluated roots and nonzero derivatives. This is NOT a zeta source.

Tests separately check 32 small depth-ceiling cases and additional elementary
bounds. These are finite cases, not independent infinite theorem counts.
`--emit` writes a proposed receipt and prints EMITTED_ONLY; it performs neither
inventory authentication nor an accepting validation.

The following final commands completed successfully in this author session.
Both accepting commands printed PASS_BUB26_BOUNDED_EXACT_CHECKS_ONLY; both

The test suite has five methods. Its CLI method first accepts a pristine
external receipt, then executes ten actual rejecting subprocesses in that
interpreter mode: false RH flag, false gap-free flag, reduced depth, floating
height, Boolean count, changed parent, changed rho, overstated clean count,
missing dyadic row, and duplicate JSON. Each refusal must have nonzero exit
status and a REJECT diagnostic. Ordinary and optimized modes execute the SAME
implementation; they are not independent numerical or mathematical reviews.

The final delivery is also checked by clean ZIP extraction and by applying an
add-only patch in a separate minimal Git fixture with an unrelated sentinel
and an exact copy of the parent proof. Those fixtures are not a complete
Riemann repository checkout. They do not rerun the parent numerical campaign.

## Limits and unperformed checks

No actual xi/zeta value, derivative, new zero, contour winding, high-height
zero census, or numerical integral is evaluated. No universal arbitrary-height
contour program is implemented. The dovetail in PROOF Section 6 is an existence
algorithm; its termination at arbitrarily large clean bands uses the imported
classical theorem, not an executed infinite search. No runtime bound, explicit
new band endpoints or all-band common finite depth is supplied.

No predecessor test suite, full repository validator/build, Lean/kernel proof,
remote CI, or non-author review is claimed. Linux symlink rejection is present
in inventory handling but has no dedicated mutation fixture in this packet;
no Windows run or symlink-capability result is asserted. A malicious replacement
of both checker and all checksums is outside its internal-integrity guarantee.

The parent manuscript was read and its exact 20032-byte Git blob and SHA256
were checked against the published source; SOURCES.json retains that identity.
The new standalone path has no collision with the earlier BHH26 variants.
Publication is intended as one additive commit on its own draft PR stacked on
PR870, with no merge, prior-file modification, mathematical status promotion,
workflow or permission change. Remote object identities and the final exact
head are recorded separately after publication, not guessed in this file.
