# Independent exact-code audit of the K839 checkpoint adapter

I regenerated the staged C++ file in a private temporary directory, byte-compared it with the retained test staging, and read its unified diff against the pinned vendor verifier. I also ran a pause/resume state comparison and two rejection tests using the retained staged binary and the original first-window fixture. These checks support exact continuation of the vendor DFS from a genuine checkpoint with bound inputs. They do not complete either later-window search, rerun the source build, or certify an arbitrary serialized state. ## Transition equivalence and counters

The stager checks the pinned vendor SHA-256 c30310214c121d0acf4b4ae562f396c1e13be13992b1f01e02df584dbd602142 and requires one occurrence of each insertion anchor. The regenerated output matched the retained test C++ before the tests. The unified diff inserts headers, checkpoint code, two error descriptions, CLI wiring, and load/save calls. The span/pruning rules, basic and affine acceptances, choice of widest gap (including tie order), midpoint, child push order, unresolved-box handling and original statistics increments are unchanged. The optional checkpoint-free invocation follows the same search transitions.

The original DFS pops the final active stack entry. On a split it pushes the upper child first and the lower child second. Thus the lower child is popped first. The adapter writes the active prefix in ascending stack-index order and reloads in that same order, restoring the exact logical stack rather than permuting branches. Each active box is written as its lower/upper integer pair for every gap. Slots beyond the active prefix are never read before overwrite. The five counters are nodes, leaves, basic, affine, and maximumStack, with stack size a separate state field.

The checkpoint is taken at the top of the loop before pop, after all operations on the preceding node. In particular a pruned or accepted node reaches the checkpoint through the next loop iteration, and a split reaches it after both child writes and the maximum-stack update. Error exits before a quiescent boundary cannot be saved as a success. The final save takes place only when the stack is empty. The trace state has an elementary invariant. Starting with one pending box, an acceptance decreases the pending size by one and increases both nodes and leaves by one. A split increases pending size by one and increases nodes only. At every checkpoint, nodes+1=2 leaves+pending and leaves=basic+affine. The C++ load checks these along with the stack-capacity checks and endpoint order/range. Source scratch fields base_, ranges_, kernelBounds_, and potentialBounds_ are filled in the current node's basic/affine path before use, so restoring them is unnecessary. lastBox_ is set on the branch that reports an unresolved node. The certificate, potential representation and range-minimum table are rebuilt from the bound inputs.

This gives an induction on the deterministic transition map. A fresh start begins at the original root, and a genuine checkpoint loads exactly the complete next-step state. Successive original transitions then agree until completion or the original unresolved/limit branch. A stopped run can redo work since the latest durable checkpoint, but does not skip it. The optional pause flag exits with 75 at the saved pre-pop state. To resume past that point the caller should omit the pause or select a later count. If the search has just emptied the stack, the terminal save and success supersede a test pause at that same count.

## Binding, durability and evidence boundary

The C++ identity field is an opaque lowercase hex tag supplied by the caller. In the production wrapper the tag is the SHA-256 of sorted JSON containing the raw and staged source hashes, parameter-generator and generated parameter hashes, input JSON and kernel-table hashes, compiler version string, and compiler flags including point count. The wrapper also logs the executable digest. The inherited flock covers its work directory while a supervised child remains alive. Use the production wrapper, the reviewed preflight inputs and an exclusive work/result directory pair. The C++ executable alone does not compute this input manifest or enforce exclusive direct CLI use.

The checkpoint writer outputs a sibling temporary file, closes and fsyncs it, atomically renames it onto the active checkpoint, then fsyncs the parent directory. This is the intended POSIX durability sequence. On a crash before rename the previous checkpoint is unchanged and a stale temporary file has no effect on load. A crash in the rename/sync gap can leave the old or new state depending on filesystem recovery. Both are valid prefixes if generated by the verified single-writer procedure. An I/O failure prevents the current invocation from reporting success. The wrapper's JSON reports use an atomic replace, with the durable search state held separately. The completed result requires native zero exit, exact agreement with all five expected counters in stdout, and matching terminal checkpoint counters.

The structurally valid state is **not** a certificate that its omitted prefix was traversed. For example, a correctly tagged fixture with nodes=1, leaves=1, basic=1, affine=0, maximumStack=1, pending=0 and a valid end marker satisfies all listed invariants and the standalone executable would skip the loop. The wrapper would reject those deliberately wrong final totals, but exact author totals themselves could also be written into an artificial empty state. This is a logical limitation of the format. Do not load hand-authored or externally supplied checkpoints as proof. Scope release claims to trusted local continuation from a fresh root, with preserved attempt logs and input binding. A checksum can detect accidental mutation, while authenticating an externally supplied prefix requires a stronger provenance or replay mechanism.

The checkpoint-specific integer arithmetic does not affect the pinned second/third expected counts, both below \(6\cdot10^8\). On load, nodes is capped at half the uint64 limit, leaves is at most nodes, and pending is below the fixed stack capacity. A hypothetical overflow in the right-hand side of nodes+1=2 leaves+pending would yield at most a few hundred, whereas overflow requires leaves and hence nodes to be near the half-limit. It cannot pass equality. A subtraction form or an explicit checked add could make this argument unnecessary. Original grid coordinates remain signed 32-bit integers and are range-checked against the loaded certificate. Restored genuine boxes obey the same arithmetic bounds as fresh ones. Treat the adapter as scoped to the pinned runs, without claiming behavior across arbitrary counter wrap or unrelated toolchains.

A minor material hardening is to make the already-completed fast path compare the full expected counter set and saved observed output, not just nodes and the empty stack. The normal completion branch already checks that stronger condition. This avoids accepting a stale or inconsistent terminal report on later supervisory invocations. Separate result directories or an equivalent lock prevent report collisions between work directories.

## Independent observed tests

Using the staged verify7 and original first-window parameters/table, I paused into a private temporary state at 100 nodes, resumed and paused at 101, then compared that byte stream with a straight run paused at 101. They were identical, including active-box order and counters. The state SHA-256 was ea84195b1b7b0c84108635d334c6f3c507a7d203c3b93f01ae25697322f1361d. At node 100 there were 32 leaves, 32 basic acceptances, zero affine acceptances, maximum stack 37 and 37 waiting. At node 101 the respective values were 33, 33, zero, 37 and 36. Every intended pause returned 75. Replacing the identity and, separately, corrupting the end marker gave checkpoint error and exit 5. No production state or vendor file was edited. These short tests exercise serialization and immediate continuation. The general trace equivalence comes from the transition proof above, with later-window completion requiring actual final reports.
