## Canonical rule

An issue is **not** a theorem node merely because it contains a proposed proof, numerical output, or a detailed task specification. It enters the scientific registry only when one of the following exists:

1. an exact PR/head/path/internal claim object;
2. an exact issue-level counterexample or correction whose evidence is self-contained;
3. a controlling review that fixes the lifecycle of an earlier wrapper;
4. a computation record with checker, result, hashes, method contract and theorem dependency.

All other issue prose is retained as historical methodology and excluded from proved-only reachability.

## Methodology that remains useful

The early issue wave developed durable review habits even when the individual route failed:

- finite witness first, with interval arithmetic and explicit tail budgets;
- independent replay and source/result separation;
- exact failure certificates rather than silent numerical non-success;
- feature-space completeness audits before interpreting a positive finite search;
- distinction between a positive source, a signed observation and a model-output allocation;
- fail-closed primal/Farkas alternatives for finite source/capacity problems;
- explicit lifecycle: proposal, correction, review, supersession, archive.

These principles survive as project methodology. The corresponding issue proposals do not survive as scientific claims unless separately published and reviewed.
